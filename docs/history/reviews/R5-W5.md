## What was checked and held

- **minisign parsing**: four lines exactly; the key id is taken from the signature and the key is picked by id. Lengths are 42, 74 and 64 bytes. `ED` uses BLAKE2b-512 and `Ed` signs the raw bytes. The global signature covers `signature || trusted comment`, so editing the comment fails. Input caps are 4 KiB for a signature, 1 KiB for the comment and 1 KiB for a key. A known id with the wrong key bytes fails.
- **Index chain**: the root verifies `keys.json` only. The root inside `keys.json` is rejected at parse time, and an index signed by the root gives `UNKNOWN_KEY`. A key id is checked against the key it names. A revoked key gives `REVOKED_KEY` before any signature work. The order is keys, signature, shape, sequence, then expiry, and it now holds against the registry's keys high-water too (F3). Rollback and keys replay are refused after a restart (`replayedIndexIsRefusedAlsoAfterARestart`, `keyRotationAndRevocationTakeEffectAtTheNextFetch`). A stale or failed copy is shown but never installable, and it now also expires on a live process (F1).
- **Fetcher and HTTP client**: the allowlist (https, exact host, port 443, no user info or fragment) is checked on the first URL and on every redirect target before `openConnection`. Redirects are capped at 5 hops. `instanceFollowRedirects=false`. A relative `//evil` Location resolves to a refused host. `Accept-Encoding: identity`. Size is bounded by `ref.size` while streaming, and a Content-Length that disagrees is refused. A resume needs an ETag and sends `If-Range`. A `200` on a range restarts from 0, and a `416` drops the partial. The sha256 is checked at the end of the stream, again in `commitPartial` before the rename, and again by the inspector (sha256 and signer). A partial is never committed without a full hash. Temp files go in `finally`, and stale partials and temp files are cleared after 7 days.
- **Blob store**: `Sha256` is `^[0-9a-f]{64}$`, and bundled names match `FILE_NAME_RE` (starts alphanumeric, no `/`), so there is no traversal (`../etc/passwd` is refused in a test). Concurrent use of one digest was the gap, fixed in F2.
- **ApkInspector**: it refuses more than one signer or none on both paths. Under Android 9 `GET_SIGNATURES`, multiple v1 signers give multiple entries and are refused. The file's own sha256 must equal the signed index's value before the signer is even considered, so a v1-only or Janus-style trick needs a signed index naming that exact file. Package and versionCode are not compared to the index inside W5 (`ArtifactRef` has no package), so W8 must do that (S1).
- **Pins**: the asset matches `PinnedLauncher` (sha256 `26461a1f...a6897`, 270,885 bytes) on the maintainer's machine with `shasum`. The release cert DER sha256 is `57641815...05132`. Both seed signatures verify with the real minisign 0.12 against the public keys in the secrets directory. `TrustRoots.INDEX_ROOT_PUBLIC_KEY` equals `index-root.pub`.

## Test quality

The tests mostly prove what they claim. Strong points:
- interop vectors made outside Kotlin;
- the real minisign seed;
- the user CA HTTPS server for the MITM property;
- real signatures through the registry.

Gaps:
- Before R5, nothing tested staleness over time, concurrency, the keys order or the out-of-range date. Each now has a test.
- `SignerDigestsTest` covers only the digest rules, not PackageManager behaviour on Android 9 or with rotation. That needs the emulator matrix (SECURITY 6.3).
- The "refused before connecting" redirect test relies on the failure type, since `evil.example` would not resolve anyway. That is acceptable.
