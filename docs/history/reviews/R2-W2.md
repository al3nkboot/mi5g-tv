Files: `adb/session/src/test/resources/watchdog/16-arm-home-watchdog-a.txt`,
`.../17-arm-home-watchdog-b.txt`.
W2's copies cited W3 commit c661334. W3's R1 review re-recorded goldens 16, 17, 19, 46 at commit
3db9946: a preparatory `'rm' '-f' '<token file>'` line now renders before the template, and the
pgrep/pkill patterns are bracketed (`[c]leanyourtv-rollback-TOKEN`). The watchdog `sh -c` line
itself is byte-identical between c661334 and 3db9946. Verified independently with a PCRE build of

### AUTH / signing oracle: no path signs anything but a 20-byte token with the SHA-1 DigestInfo
Severity: none (pass). Files: `adb/wire/.../AdbAuth.kt`, `android/platform/.../KeystoreAdbSigner.kt`,
`adb/wire/.../Connection.kt:handshake`.
The handshake refuses any AUTH token whose payload is not exactly `TOKEN_BYTES` before building an
`AuthToken` (`Connection.kt`, the `m.payload.size != AdbProtocol.TOKEN_BYTES` guard). `AuthToken`
re-checks 20 at the type level (`Wire.kt`, R0: 4). Every engine (StrongBox, TEE, wrapped software,
`SoftwareRsaAdbSigner`) signs only through `AdbSignature.sign`, which prepends the fixed 15-byte
SHA-1 `DigestInfo` and signs via JCA `NONEwithRSA` (PKCS#1 v1.5), so the signed input is always
the 35 bytes `DigestInfo(SHA-1) || token`. The raw-RSA-cipher plug point of spike S2 mode 1 is not
used, so the residual "adbd picks the payload length" of S2 is removed; this is S2 mode 2. The
handshake signs exactly one token per connection (the `signatureSent` flag means a second AUTH
goes to the public-key path and a third is `Auth.Denied`), so a hostile adbd cannot farm multiple
signatures over attacker-chosen tokens in one session. `SecretBox` never signs. N2's plain-mode
relay remains the documented residual, reduced exactly as SECURITY 9 and threat N2 state.

### Key material: non-exportable, not logged, not backed up; AES-GCM wrap with fresh IVs
Severity: none (pass). Files: `KeystoreAdbSigner.kt`, `SecretBox.kt`.
Keystore key is `PURPOSE_SIGN` only, `DIGEST_NONE`, PKCS#1 padding, StrongBox then TEE; the private
half never leaves the Keystore. The software fallback seals PKCS#8 with `SecretBox` (AES-256-GCM
under Keystore key `cleanyourtv.wrap.v1`, StrongBox when available) in `noBackupFilesDir`; a fresh
12-byte GCM IV comes from the provider on every `seal` and is checked for length. No key bytes are
logged: `provisioningNotes` hold only skip reasons and exception class names. `reset()` deletes
both aliases and the sealed file. Matches SECURITY 4.1 and threat P1. (ART-only, so exercised at
I1, not on the JVM; `SoftwareRsaAdbSigner` is the JVM stand-in and is self-tested.)

### Wire reader: every length bounded before allocation
Severity: none (pass). Files: `adb/wire/.../Protocol.kt`, `Streams.kt`, `Connection.kt`.
`FrameCodec.parseHeader` rejects bad magic, unknown commands and any length over the per-command
bound before a payload byte is read: WRTE 1 MiB, CNXN/AUTH/OPEN 256 KiB, OKAY/CLSE/STLS/SYNC 0;
`readMessage` verifies the checksum and refuses truncated header or payload. Shell v2 bounds each
packet at 1 MiB, forces a 1-byte exit packet, and accepts only stdout/stderr/exit ids from the TV.
Sync bounds DATA at 64 KiB, FAIL at 4 KiB, paths at 1 KiB, and a pull is refused before the bytes
over `maxBytes` are kept. Banner refuses a peer window under 4 KiB. `HostileFrameFuzzTest` is the
bounded random-frame substitute for Jazzer (see Fuzz). Matches N7 and D-W2-2.

### Flow control, slow-loris and zero-window
Severity: low. Files: `Connection.kt` (`StreamImpl`, `pump`), `android/platform/.../PlainSocketFactory.kt`.
Per-stream inbox is bounded (`INBOX_CAPACITY = 4`); a peer that overfills it is cut off with a
`Protocol` error that tears down the whole connection (`aPeerThatIgnoresFlowControlIsCutOff`).
Writes send one WRTE and wait for an OKAY, chunked to the peer window, so a zero-window peer pins
no extra memory, and the session wraps every transfer write in an idle clock
(`stalledPushTimesOutOnTheIdleClock`, `hangingInstallTimesOut`). Memory is bounded throughout.
One residual: the message pump's `FrameCodec.readMessage` has no idle read timeout and
`PlainSocketFactory` sets no `SO_TIMEOUT`, so a peer that sends a header and then dribbles or
stalls mid-frame parks one Dispatchers.IO thread (and up to a 1 MiB buffer) on a blocking read.
It is not pinned forever: the 60 s idle close (no holder) or a 20 s/5 s keepalive ping miss (held)
closes the socket and unblocks the read. Defense-in-depth suggestion for the owner below.

### Session: single-flight, holds, reconnect, cancellation, 60 s idle
Severity: none (pass). Files: `AdbTvSession.kt`, `Support.kt`, `AdbSessionManager.kt`.
One mutex per session serialises every call (`call(...)`). `Transport.Closed` retries once only
for the idempotent classes, never `NEVER`; timeouts are never retried. Holds are reference counted;
the last release arms the 60 s idle close (`noHolderClosesTheSocketAfterSixtySeconds`) and a held
session pings every 20 s. Reconnect is 5 attempts, full-jitter backoff 500 ms..8 s, with `Auth`,
`Policy` and `NoShellV2` short-circuiting the loop
(`reconnectBudgetEndsInFailedThenCallsThrowClosed`, `droppedSocketWhileHeldReconnects`).
Cancelling a call sends CLSE and leaves the connection up (`cancelledReadLeavesTheConnectionUp`,
`cancellingACallLeavesTheConnectionUp`); the frame write runs under `NonCancellable` so frames go
out whole. Matches ARCHITECTURE 3.3, 3.4, 3.6, 3.10.

### Identity (D37/D38): byte-compatible, wrong TV refused on every connect
Severity: none (pass). Files: `Support.kt` (`Identity`), `AdbSessionManager.kt`, `AdbTvSession.kt`.
`TvId` = first 16 hex of `sha256(ro.serialno + ro.product.device)` on the raw getprop values, no
separator and no trimming (`Identity.tvId`), byte-compatible with W6's `restore.sh` and pinned by
`IdentityAndQueueTest.tvIdFormulaIsPinned` and `PersonaFidelityTest.tvIdFollowsD37`. Identity is
read before anything else on the manager's open, on `connectOnce`, and on every reconnect; a
mismatch is `Policy.WrongTv` and the socket is closed with nothing sent
(`sessionManagerRefusesTheWrongTv`, `aDifferentTvAtTheAddressIsRefusedBeforeAnythingElse`,
`aDifferentTvAfterReconnectNeverRunsAStep`). The `wrongTvOnReconnect` fault exercises the reconnect
case. Matches D-W2-10 and threat N1 (presence check lives in the UI layer, as designed).

### PmGuard: never chains, T4 is the only exception
Severity: none (pass). File: `Support.kt` (`PmGuard`).
`refusal` returns null unless the line holds a `pm`/`cmd package` write verb together with a chain
character (`; & | newline CR backtick $(`), and then refuses unless `WATCHDOG_RE` matches the whole
line. The regex is written from the template text (no `:core:ops` dependency), with only seconds
`[0-9]{2,3}`, the token `[0-9a-f]{16}` (one value, backreferenced in all three places), the stock
`PACKAGE_RE` package and the same-package component with a `CLASS_RE` class as variable parts;
every other byte is fixed. The fake adbd enforces the same rule at exit 126 and records a violation
(`FakeShell`, `interpreterRefusesChainedPmWrites`). The quoted `sha256sum '<RemotePath>'` is inert
(`RemotePath` admits only `[A-Za-z0-9._-]` segments under a fixed root). Matches SECURITY 3.5/3.6,
D-W2-9/9a.

### Fake adbd fidelity to the Mi TV capture
Severity: none (pass). Files: `testing/fake-adbd/.../Persona.kt`, `Shell.kt`, `FakeAdbd.kt`,
`PersonaFidelityTest.kt`.
The Mi TV persona reproduces the redacted capture byte for byte: `getprop`, `pm list packages -f`,
`-3`, `-d` (before and after debloat), `settings list` for all three namespaces, and the HOME
activity (`PersonaFidelityTest`, 6/6). The shell interpreter mutates a `FakeTv` so lists after a
write are real, real AUTH verifies signatures with the advertised key, and the fault knobs cover
latency, bandwidth, drop, half-open, stalled push, hostile flow control, pm delay/busy, hanging
install, single-thread, Allow behaviour, garbage before/after CNXN, split packets, wrong TV on
reconnect, reboot timings, STLS-only and refused opens. It is a faithful and adversarial target.
Remaining gap is inherent, not a defect: the capture is one Android 9 Mi TV; the TCL and Chromecast
personas are synthetic (marked `synthetic`), and Android 11+ wireless-debugging/TLS and SPAKE2
pairing are out of 0.1 scope, so they are not exercised on hardware until 0.2. This is the right
line to draw for 0.1 and matches D9/Q5.

### Fuzz: property test as a Jazzer substitute
Severity: low (acceptable). File: `adb/wire/.../HostileFrameFuzzTest.kt`.
A fair substitute within the forge constraint (no Jazzer agent/native driver, D-W2-17). It drives
random and mutated bytes into the frame decoder, the shell v2 reader, the sync reader and a live
connection, and accepts only a decoded value, end of stream or `AdbException`; it bounds every
allocation against the per-command cap and times out a hang. Budget is a wall-clock share
(`-Pcleanyourtv.fuzzSeconds`, 15 s in `check`, 600 in CI) with a replayable seed. The honest
limitation is that it is not coverage-guided, so it will not minimise or steer toward new branches
the way Jazzer would; the mutation set (header-field overwrites, truncation, boundary lengths) is
reasonable but hand-chosen. Fine for 0.1; see the owner note to keep the CI 10-minute run and
record seeds.

## Required fixes for the owner (W2)

None blocking. Recommended before I1, all low severity:

1. Wire-layer idle read guard (defense in depth). Give the message pump its own idle read timeout
   or set `SO_TIMEOUT` on the plain socket so a header-then-stall peer cannot park an IO thread and
   a 1 MiB buffer until a higher layer tears the socket down. Today the 60 s idle close and the
   20 s ping bound it, so this is hardening, not a hole. Add a test: a peer sends a valid header
   then no payload, and the connection is reclaimed within a bounded time with no leaked thread.
2. `SecretBox.open` length check is `> 1 + IV + TAG` (strictly greater), which would reject a
   validly sealed empty plaintext. Harmless today (the sealed value is always a non-empty PKCS#8
   key), but `>=` is the correct bound; tighten it or add a comment that empty is never sealed.
3. Fuzz coverage note: keep the CI 10-minute run (`-Pcleanyourtv.fuzzSeconds=600`) wired in `pr.yml`
   and record the printed seed on any failure so it replays; consider adding a couple of
   capture-derived seed corpora (a real CNXN banner, a real sync DATA burst) so the random walk
   starts near valid frames more often.

## RFC rulings

- RFC-W2-1 (`@RawShell` opt-in in `:adb:session` for `SessionLines`, five constant lines):
  APPROVED. The session must read `getprop` for D37 identity before any caller line is sent, so it
  cannot source these lines from `:core:probe` or `:core:ops`. The five lines are read-only
  constants in one `internal object`; `sha256sum '<RemotePath>'` is the only one with an argument
  and the path grammar makes it inert. W3 must add `tv.cleanyour.adb.session.SessionLines` to the
  single-call-site lint's `@RawShell` allowlist.
- RFC-W2-2 (`AdbConnection.isClosed` and `invokeOnClose`): APPROVED. Both are additive; the frozen
  `features`/`maxPayload` keep their names and types and section 5.3 already elides the constructor
  as "sketch; W2 owns the shape". They let the session learn the pump died without polling, which
  is cheaper than a per-check ping round trip. No caller outside W2 touches `AdbConnection`.
- RFC-W2-3 (`AdbSessionManager` constructor shape): APPROVED (documentation only, not a section 5
  type). The defaults are sound; `blobIo` for test dispatchers is a clean seam and production keeps
  `Dispatchers.IO`.

  reasons in the I1 notes, never a serial); `adb backup` yields no app data; "Reset my key" makes
  the TV ask again with a new fingerprint.

- Idle/keepalive on the real set: hold a session, leave it untouched past 20 s and confirm the

- Reboot path once (if the user is willing): `reboot()` then `awaitBoot` returns `Back` with a boot

- If a second Android TV is on the LAN, point the app at the wrong IP once and confirm
  `A different TV answered at this address` with nothing written (N1/D37 on real hardware).
