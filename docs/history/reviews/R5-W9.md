## Merge procedure for the coordinator

1. On main: `git merge --no-ff w9`. Expect no textual conflicts; if a later main change makes one
   in the files of step 1 above, keep both sides (all edits are additive). The timeout conflict is
   already handled on w9.
2. Regenerate once on the merged tree: `scripts/update-verification-metadata.sh` (rerun if Maven
   answers 5xx). Review the diff: additions only, each new component is a new trusted artifact.
   Commit it as "Verification metadata after merging W9".
3. Verify: `scripts/build-on-forge.sh check checkModuleGraph :app:assembleDebug`.
4. From then on, every stream merged later (w2, w3, w8 have build file changes) needs the same
   step 2 in the merge, before its verifying build. Branches never hand-edit
   `gradle/verification-metadata.xml`; if one does and it conflicts, take main's copy
   (`git checkout --ours gradle/verification-metadata.xml`) and regenerate. A dependency bump
   anywhere needs step 2 in the same change, or every later build fails at configuration.
5. w3 carries its own "five minute Gradle test timeout" commit; expect it to meet main's
   identical lines in build-logic and keep main's.
6. Set the repository variable `CYT_E2E_REQUIRE_ALL=1` once E2eWiring is filled in (I5), and pin
   pr.yml's actions the same way as W9's.
