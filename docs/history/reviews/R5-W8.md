# R5 review of W8 (flows, screens, Android glue)

Reviewer: R5 per-PR gate, 2026-10-19. Scope: `git diff main...w8` (14 W8 commits, 230 files) against
PRODUCT-SPEC section 4, section 5, the W8 row, D7, D16 to D19, D23, D24, D35, D37, D38; UX.md flows and
edges (2, 4.1 to 4.14); SECURITY 4.2, 4.3, 4.5, 4.6, 4.9; DECISIONS-W8.md; RFCS.md (now docs/rfcs/W8.md).

## Verdict

**MERGE AFTER FIXES.** The fixes are on the branch (commits below) and the batched build is green
(see "Build"). What is left is listed under "Open findings"; none of it blocks the merge, and the
two Medium ones are best done at the W7 swap and the W3 merge, where the code they need lands.

The shape is sound: one machine per screen family on the frozen `Machine` contract, a single
app-wide `GateKeeper`, `TvAccess` always passing the expected TvId, a `SessionEnd` that keeps the
D7 promise, and a manifest that matches SECURITY 4.2. The defects were in the edges: two paths that
left the wizard stuck on "What we found", the debug_off rule firing for a write that never ran and
missing for writes that did, a Done line that could claim "Debugging off" when it was not, and a
foreground service that could crash the app on a short run.

## RFC rulings

| RFC | Recommendation | Reason |
| :- | :- | :- |
| RFC-W8-1 SetupIntent misses buttons | **Change**: add `SetupIntent.StopAction(action)` and `SetupIntent.RejectIdentity` to the frozen set; keep `back(): Boolean` as a machine method, not an intent. | The two intents are plain events and belong in the sealed set; back must answer synchronously whether it consumed the press, which an intent cannot. The positional PRIMARY, SECONDARY, TERTIARY mapping is acceptable because it lives in one table (`onStopAction`) next to `stopKeys`, which fixes the button order per case. |
| RFC-W8-2 SetupState has no room for presentation details | **Accept** (bless the derived side state). | `SetupExtras` is derived only and never a source of truth; adding an `extras` field to all ten frozen subtypes would churn section 5 for no safety gain. Condition: nothing that gates a write may live only in extras (today it does not: the identity gate is `DoorPhase.IDENTITY` in the state). |
| RFC-W8-3 StopCase and StopCard grown | **Accept**. | Exactly what R0: 2 allows (additions only, `tertiary` defaulted). |
| RFC-W8-4 Credential gate for app-level actions | **Accept for 0.1** with the placeholder id, documented; revisit `confirmApp` in 0.2. | The placeholder pass can never start a plan (the engine checks `pass.tvId == plan.tvId`, and no TvId is all zeros in practice), and `forcePrompt` makes every app-level action prompt. Small change: do not cache that pass (O9). |
| RFC-W8-5 No PlanRequest for the restart test | **Accept the proposal** (W3 adds `PlanRequest.Reboot` with `PlanKind.REBOOT`); the direct `TvSession.reboot()` stays as the interim for 0.1. | ARCHITECTURE 2.4 lists Reboot as its own plan, and a journalled reboot makes the run log and the "Show details" stop card truthful after a restart that does not come back. It changes nothing that needs undoing, so it should carry no gated privilege, which keeps the D17 prompt count unchanged. |
| RFC-W8-6 Module card answer detection | **Accept the seam; defer the Prober API** to 0.2. | `CardAnswerDetector` defaults to unknown and M3c offers the two manual outcomes, which is honest for 0.1; a screenshot-based answer would be guesswork until the launcher's provider exists. |
| RFC-W8-7 D16 misses USE_BIOMETRIC | **Accept**: amend D16 to add `USE_BIOMETRIC`, and W9's `aapt2 dump badging` assertion lists it. | `BiometricPrompt.authenticate` requires it; it is a normal, install-time permission with no prompt and no data access. The alternative (the deprecated keyguard screen on every API level) loses biometrics and the BIOMETRIC_STRONG floor D17 asks for. |
