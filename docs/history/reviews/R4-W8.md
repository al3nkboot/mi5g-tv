# R4 review of W8 (T8 A and B): UX and UI of every screen against the mockups

Reviewer: R4 gate, 2026-10-19 (did not write the branches). Inputs: main at `d87903b` (every
screen on the real `:ui:design` components), the 728 goldens under `feature/*/src/test/screenshots/`

the approved mockups (`app-design/mockups/index.html`, 01 to 08), PRODUCT-SPEC section 4 (final copy)

the R4-W7 and R5-W8 reviews. Fixes are on branch `r4fix` (worktree `cyt-wt/r4fix`), commits below.

## Verdict: PASS WITH FIXES (applied on `r4fix`, goldens re-recorded)

The 20-odd screens are the mockups, built: the eight mockup screens match frame for frame (tokens,
rhythm, one primary per screen, the quiet overline, the glass chip, the Off / Kept pills, the glass
check mark on Done), and the twelve screens the mockups never drew (stop cards, Manage, the settings,
modules, restore point) read as the same family: one title, one sentence, one list, one pill. Copy is
spec section 4 line for line (see "Copy"), the default path shows nothing it does not need, and
every advanced option sits behind "Customise", a chevron row or a sheet. What held it back were
layout truths the goldens made visible: the safety sentence of S3 cut in half under the primary on
the reference phone, the stop cards of Welcome and Done rendered with their way out below the fold,
dock names wrapping at 100% and breaking mid-word at 200%, and the countdown ring scrolling off the
screen at 200%. Those, the guard gap, the two theme pickers that did not match and the golden size
are fixed below. Light mode contrast, RTL and the D-numbers pass.

## Rulings on the items raised

1. **S4b "Prime Video, and Live TV"**: not a defect. The sentence is built with `android.icu.text.ListFormatter`
   for the person's locale; the serial comma is what CLDR prescribes for en-US and the goldens record
   under en-US. en-GB and en-IN format "Prime Video and Live TV", which is the spec's British source
   line. Keep the formatter (it is also what makes the sentence right in every other language); do
   not hand-join. If the goldens should read like the spec, record them under `en-rGB` (a one-line
   qualifier change), which I did not do because it would move every golden for no product change.
2. **The S3 safety line under the sticky bar**: a defect (H1), fixed by pinning the line with the
   button it protects, which is where UX 7.3 rule 8 wants it. On the reference 360 x 780 the content
   column now ends on the home screen row with the whole safety sentence and both buttons in view.
3. **Dock rows at 200% ("YouTu be")**: a defect (M1) and also visible at 100% with a full dock
   ("Prime / Video"). Fixed with `DockRow` (controls drop under the name when its longest word does
   not fit beside them), the 48 dp targets kept.
4. **Forget, Reset key, Delete everything and Remove as primary pills**: right as they are. The design
   system reserves the outlined danger pill for exactly one action, "Put everything back", the only
   one that reverses the TV wholesale (DESIGN-SYSTEM 8.1, 9 "Danger"). Forget, Reset my key and Remove
   are undone with a few taps (set up again, trust again, add again), each sits behind a sheet whose
   title is the question and whose body states the consequence, and each is behind the credential
   prompt (D17). The white pill is the app's "proceed" affordance and the sheet carries the weight; a
   red outline on four more sheets would stop red meaning anything. "Delete everything" is the only
   phone-side action with no way back and is the one I weighed longest; its sheet body already says
   so in plain words, and a second red button would weaken the single-danger rule for a case the copy
   handles. The guard on all four is right, since each is a confirm (SECURITY 4.3).
5. **Unguarded writes (StopCard secondary, drift banner, ThemePicker)**: guard them. The rule should
   be the write, not the visual weight: every control whose tap starts a change on the TV drops a tap
   through an overlay, and the hint says why. "Undo what we did" runs a rollback plan, "Restore mine"
   pushes the config, a theme row on Manage applies at once; the wizard's theme sheet only changes
   the draft and stays unguarded. Fixed in `:ui:design` with parameters that default to off, so Back,
   Cancel, "Leave it as is", "Keep Projectivy" and "Show details" never block (R5-W8 O1 holds).
6. **Golden size**: half scale everywhere, no Git LFS. Half scale keeps the goldens readable (every
   finding above was made on half-scale images), cuts the repo's goldens from about 107 MB to about
   45 MB, and the ATF checks still run on the full xhdpi render. LFS would add a tool every clone and
   the forge rsync must carry, a 1 GB free quota that 4 variants of 180 screens re-recorded a few
   times would reach within months, and a diff view that stops working on GitHub for the one kind of
   file a reviewer wants to see. The history keeps the 82 MB already committed; that is a one-off.
   Two habits keep it small from here: re-record only the modules a change touches, and never
   re-record the whole set for a cosmetic difference.
